1. Цель и задачи работы

Цель работы: ознакомиться с принципами непрерывной интеграции и доставки (Continuous Integration / Continuous Delivery, CI/CD) в контексте разработки, сборки и комплексного тестирования микропрограммного обеспечения серверных платформ (OpenBMC). Сконфигурировать сервер автоматизации Jenkins в контейнерной среде Docker и разработать декларативный сборочный конвейер Jenkinsfile (на языке Groovy), объединяющий запуск эмулятора QEMU, тестирование Redfish REST API, проверку веб-интерфейса Selenium и нагрузочные испытания Locust с обязательной публикацией отчётов в артефакты сборки.

Задачи:

  1. Изучить концепции CI/CD, архитектуру сервера Jenkins (Controller, Build Executors), механизмы декларативных сборочных линий (Declarative Pipeline) и плагины архивации артефактов (archiveArtifacts, junit, publishHTML).
  2. Разработать конфигурацию развёртывания сервера Jenkins в среде Docker (файлы docker-compose.yml и кастомный Dockerfile со встроенным инструментарием Python, Chromium, QEMU ARM и библиотеками тестирования).
  3. Спроектировать и реализовать декларативный сценарий Jenkinsfile со следующими стадиями:
    • Stage 1 (Checkout & Setup): подготовка каталогов артефактов (reports/, screenshots/) и фиксация параметров среды окружения;
    • Stage 2 (Start OpenBMC QEMU): фоновый запуск эмулятора платформы OpenBMC и верификация готовности сетевых интерфейсов через Health-check опрос;
    • Stage 3 (OpenBMC API Tests): запуск модульных автотестов DMTF Redfish API и IPMI (PyTest) с генерацией отчётов JUnit XML и HTML;
    • Stage 4 (OpenBMC WebUI Tests): запуск автотестов веб-интерфейса OpenBMC (Selenium WebDriver в headless-режиме) со сбором скриншотов экрана;
    • Stage 5 (OpenBMC Load Tests): выполнение сценария нагрузочного тестирования (Locust в headless-режиме) с генерацией HTML-дашборда и CSV-метрик;
    • Post Actions / Teardown: гарантированная остановка фонового эмулятора OpenBMC, архивация артефактов, публикация результатов тестов JUnit и агрегированных HTML-отчётов.
  4. Провести валидацию работоспособности конвейера, проанализировать сформированные артефакты и оформить отчёт с публикацией исходного кода в репозиторий GitHub.

2. Теоретические сведения

CI/CD (Continuous Integration / Continuous Delivery) — комплексная методология современной программной инженерии, направленная на автоматизацию регулярной интеграции кода разработчиков, его непрерывную сборку, многоуровневое тестирование и подготовку к релизу. В рамках разработки прошивок серверов (Firmware / OpenBMC) конвейеры CI/CD играют критическую роль, так как аппаратные сбои на физических серверах недопустимы. Эмуляция платформы в QEMU в сочетании с многоуровневыми автотестами позволяет выявлять регрессии на ранних стадиях до прошивки физических микросхем SPI Flash.

Jenkins — лидирующая система автоматизации с открытым исходным кодом. Основные принципы работы:

  • Jenkins Controller: координирует выполнение задач, управляет конфигурацией, пользовательским интерфейсом и хранилищем артефактов;
  • Pipeline as Code (Jenkinsfile): описание процесса сборки и тестирования в виде версионируемого скрипта в корне репозитория проекта на языке Groovy;
  • Declarative Pipeline: строго структурированный синтаксис (блоки pipeline, agent, stages, stage, steps, post), обеспечивающий предсказуемость исполнения, устойчивость к ошибкам и наглядную визуализацию на схеме Stages в веб-интерфейсе Jenkins;
  • Артефакты сборки (Build Artifacts): файлы (логи, скриншоты сбоев, бинарные пакеты, графики, отчёты JUnit XML / HTML), которые сохраняются в долговечном хранилище контроллера и привязываются к конкретному номеру сборки (Build ID) для последующего аудита.

4. Развёртывание Jenkins в Docker

Для контейнеризации сервера непрерывной интеграции подготовлен манифест docker-compose.yml и базовый Dockerfile. В образ контроллера интегрированы необходимые утилиты автоматизации (Chromium для headless-тестов, QEMU ARM для эмуляции платы Romulus, Python 3 и библиотеки pytest, selenium, locust):

# docker-compose.yml
version: '3.8'
services:
  jenkins:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: jenkins-openbmc-ci
    restart: unless-stopped
    user: root
    ports:
      - "8080:8080"      # Веб-интерфейс Jenkins
      - "50000:50000"    # Порт для подключения внешних агентов сборки JNLP
    volumes:
      - jenkins_home:/var/jenkins_home
      - /var/run/docker.sock:/var/run/docker.sock
    environment:
      - JAVA_OPTS=-Djenkins.install.runSetupWizard=false
      - JENKINS_OPTS=--httpPort=8080

volumes:
  jenkins_home:
    driver: local

Запуск контейнера выполняется стандартной командой Docker Compose:

docker compose up -d

После инициализации веб-интерфейс сервера Jenkins становится доступен по адресу http://localhost:8080.

5. Реализация сборочного конвейера (Jenkinsfile)

Ниже приведён полный листинг разработанного сценария Jenkinsfile на языке Groovy, реализующий запуск QEMU, исполнение автотестов и публикацию всех типов артефактов:

pipeline {
    agent any

    environment {
        OPENBMC_HOST    = 'http://127.0.0.1:18443'
        OPENBMC_USER    = 'root'
        OPENBMC_PASS    = '0penBmc'
        REPORTS_DIR     = 'reports'
        SCREENSHOTS_DIR = 'screenshots'
    }

    options {
        timeout(time: 20, unit: 'MINUTES')
        timestamps()
        ansiColor('xterm')
        disableConcurrentBuilds()
    }

    stages {
        stage('Checkout & Setup') {
            steps {
                script {
                    echo "▶ [Stage 1] Подготовка структуры каталогов артефактов"
                    sh '''
                        mkdir -p ${REPORTS_DIR}
                        mkdir -p ${SCREENSHOTS_DIR}
                        echo "Build: #${BUILD_NUMBER} on ${NODE_NAME}" > ${REPORTS_DIR}/env_info.txt
                        python3 --version >> ${REPORTS_DIR}/env_info.txt
                    '''
                }
            }
        }

        stage('Start OpenBMC QEMU') {
            steps {
                script {
                    echo "▶ [Stage 2] Запуск эмулятора QEMU / сервиса OpenBMC"
                    sh '''
                        python3 openbmc_service.py > ${REPORTS_DIR}/qemu_boot.log 2>&1 &
                        echo $! > ${REPORTS_DIR}/openbmc_pid.txt

                        # Цикл ожидания доступности портов эмулятора
                        RETRIES=30
                        until curl -s -f http://127.0.0.1:18443/healthz || [ $RETRIES -eq 0 ]; do
                            sleep 1
                            RETRIES=$((RETRIES-1))
                        done
                        [ $RETRIES -gt 0 ] || { echo "OpenBMC boot timeout!"; exit 1; }
                        echo "OpenBMC ready!" >> ${REPORTS_DIR}/qemu_boot.log
                    '''
                }
            }
        }

        stage('OpenBMC API Tests') {
            steps {
                script {
                    echo "▶ [Stage 3] Запуск автотестов REST API (PyTest Redfish)"
                    sh '''
                        python3 -m pytest test_api.py -v -s \
                            --junitxml=${REPORTS_DIR}/api_tests.xml \
                            --html=${REPORTS_DIR}/api_report.html \
                            --self-contained-html || true
                    '''
                }
            }
        }

        stage('OpenBMC WebUI Tests') {
            steps {
                script {
                    echo "▶ [Stage 4] Запуск WebUI автотестов (Selenium WebDriver)"
                    sh '''
                        python3 -m pytest test_webui.py -v -s \
                            --junitxml=${REPORTS_DIR}/webui_tests.xml \
                            --html=${REPORTS_DIR}/webui_report.html \
                            --self-contained-html || true
                    '''
                }
            }
        }

        stage('OpenBMC Load Tests') {
            steps {
                script {
                    echo "▶ [Stage 5] Запуск нагрузочного тестирования (Locust)"
                    sh '''
                        python3 -m locust -f locustfile.py --headless \
                            --host=${OPENBMC_HOST} -u 10 -r 2 -t 15s \
                            --csv=${REPORTS_DIR}/locust_stats \
                            --html=${REPORTS_DIR}/locust_report.html \
                            OpenBMCUser || true
                    '''
                }
            }
        }
    }

    post {
        always {
            script {
                echo "▶ [Teardown] Остановка OpenBMC и публикация артефактов"
                sh '''
                    if [ -f ${REPORTS_DIR}/openbmc_pid.txt ]; then
                        PID=$(cat ${REPORTS_DIR}/openbmc_pid.txt)
                        kill $PID || true
                    fi
                '''

                // 1. Архивирование всех файлов отчётов и скриншотов в Jenkins
                archiveArtifacts artifacts: "${REPORTS_DIR}/**, ${SCREENSHOTS_DIR}/**",
                                 fingerprint: true, allowEmptyArchive: true

                // 2. Интеграция результатов тестирования в виде JUnit графиков
                junit testResults: "${REPORTS_DIR}/*.xml", allowEmptyResults: true

                // 3. Публикация интерактивных HTML-дашбордов
                publishHTML([
                    allowMissing: true, alwaysLinkToLastBuild: true, keepAll: true,
                    reportDir: "${REPORTS_DIR}",
                    reportFiles: 'api_report.html, webui_report.html, locust_report.html',
                    reportName: 'OpenBMC Pipeline Comprehensive Reports'
                ])
            }
        }
        success { echo "✅ Все тесты в конвейере успешно пройдены!" }
        failure { echo "❌ Обнаружены ошибки при выполнении конвейера!" }
    }
}
